# إصلاح رفض دخول الجهاز (403)

تم التحقق من الجهاز المتصل Samsung SM-X210 بتاريخ 2026-10-26:

`764c419d-e847-49e8-bd1f-a816ee213aba`

السيرفر الفعلي رفض الطلب عند فحص `installationDenied()` في `ManagedSessionController`، بعد نجاح مطابقة سر التثبيت. هذا يعني وجود سجل محظور أو مرفوض أو محذوف لنفس التثبيت؛ ليس خطأ رابط القنوات. لا يمكن تحديد أي حالة من الرد القديم لأنه لا يحتوي رسالة. الأمر أدناه يعرض الحالة الفعلية.

## الرفع

ارفع محتويات `device-access-fix.zip` إلى جذر مشروع Laravel على السيرفر، مع الحفاظ على مسارات الملفات واستبدال النسخ القديمة. لا يحتوي الملف المضغوط على أسرار أو ملف `.env` أو مجلد `vendor`. لا تحتاج التعديلات إلى migrations أو تحديث Composer.

نفّذ من Terminal السيرفر:

```bash
cd /home/tclnet/public_html/iptv
php artisan optimize:clear
php artisan devices:restore-access 764c419d-e847-49e8-bd1f-a816ee213aba
php artisan devices:restore-access 764c419d-e847-49e8-bd1f-a816ee213aba --apply
```

الأمر الأول يعرض الحالة فقط. الأمر الذي يحتوي `--apply` يستعيد السجلات المحذوفة ويرفع المنع عن سجلي الجهاز العادي و`managed-` لنفس التثبيت. لا يغيّر سر التثبيت أو بيانات المزود أو تواريخ الاشتراك، ولا يمس الأجهزة الأخرى. سجل التفعيل المحظور أو المرفوض يعود إلى انتظار الموافقة؛ سجل الدخول المباشر يعود معتمداً.

بعد التنفيذ أعد محاولة إضافة رابط M3U الكامل في التطبيق. رفع الملفات وحده لا يرفع المنع الموجود في قاعدة البيانات. النسخة القديمة من التطبيق تستطيع إعادة محاولة الدخول بعد استعادة السجل؛ تعديلات Flutter المحلية تضيف توضيح السبب والتحقق من رمز الجلسة وتتطلب إعادة تشغيل البناء أو إصدار نسخة جديدة.

الرد الفعلي أظهر stack trace من Laravel؛ اضبط `APP_DEBUG=false` في `.env` للإنتاج ثم نفّذ `php artisan config:clear` حتى لا تظهر تفاصيل الخادم في الردود.

## التحقق المحلي

- جميع اختبارات Laravel: 27 اختباراً، 120 assertion.
- اختبارات Flutter لمسار إدارة الجهاز: 10 اختبارات ناجحة.
- تحليل Dart للملفات المعدلة: بلا مشاكل.
- لم يتم رفع التعديلات أو تعديل قاعدة بيانات الإنتاج. تشغيل القنوات فعلياً يحتاج تنفيذ الاستعادة على السيرفر وإعادة إدخال الرابط الكامل.
